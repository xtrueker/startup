MARCO TEÓRICO

1. Arquitectura de Sistemas y Patrones

1.1 Arquitectura Orientada a Eventos (EDA)

El sistema implementa un modelo basado en eventos para la gestión de alertas de seguridad. A diferencia del modelo tradicional de petición-respuesta, la arquitectura orientada a eventos permite que el servidor emita notificaciones automáticas a los clientes (operadores) inmediatamente después de que se registre una alerta en el sistema, minimizando la latencia crítica en situaciones de emergencia.

1.2 Patrón Cliente-Servidor y Monorepo

Se utiliza una estructura de monorepo para gestionar la coherencia de datos entre los distintos clientes (Web y Móvil) y la lógica de servidor (API). Esto garantiza que las interfaces compartan los mismos contratos de datos e interfaces de TypeScript, reduciendo la fragmentación del código.

2. Persistencia de Datos y Bases de Datos NoSQL

2.1 MongoDB como Base de Datos de Documentos

Se utiliza MongoDB bajo el modelo de base de datos NoSQL orientada a documentos. Esta elección se fundamenta en la alta disponibilidad y la escalabilidad horizontal que ofrece el sistema. Al no requerir un esquema rígido, permite almacenar datos de alertas que varían en estructura (metadatos de dispositivos, fotos, ubicación, niveles de audio) sin comprometer la integridad del sistema.

2.2 Almacenamiento Geoespacial (GeoJSON)

La persistencia de coordenadas se basa en el estándar GeoJSON. Esto permite realizar consultas espaciales nativas en la base de datos (índices 2dsphere), facilitando la detección de incidentes en un radio determinado o la asignación de recursos basados en la proximidad geográfica.

3. Seguridad e Integridad de la Información

3.1 Autenticación Basada en Tokens (JWT)

Para la gestión de accesos se emplea JSON Web Tokens (JWT). Este estándar permite una autenticación segura y "sin estado" (stateless), donde el servidor no necesita mantener una sesión activa en memoria, mejorando el rendimiento y permitiendo el escalado del backend en la nube.

3.2 Criptografía y Hashing de Contraseñas

La integridad de las credenciales de usuario se asegura mediante el uso de algoritmos de hashing unidireccional (Bcrypt). Este proceso incluye un factor de costo y un "salt" aleatorio para mitigar ataques de fuerza bruta y asegurar que los datos sensibles no sean recuperables incluso en caso de acceso no autorizado a la base de datos.

4. Comunicación en Tiempo Real y Protocolos

4.1 Protocolo WebSockets y Socket.io

Se emplea el protocolo WebSockets a través de la biblioteca Socket.io para establecer una conexión persistente y bidireccional entre el ciudadano y el centro de mando. Esto es fundamental para la transmisión en vivo de la ubicación GPS mientras una alerta de pánico está activa.

4.2 Transmisión de Video (WebRTC y RTSP)

El sistema requiere la integración de flujos de video de cámaras de seguridad. Se utiliza el protocolo RTSP para la captura de flujos IP y WebRTC para la visualización en el navegador web, logrando transmisiones con una latencia inferior a un segundo.

5. Análisis y Procesamiento Geográfico

5.1 Geometría Computacional con Turf.js

El análisis espacial se realiza mediante algoritmos de geometría computacional (Turf.js). Esto permite el cálculo en el lado del servidor de zonas de alcance, polígonos de búsqueda e isócronas, que son representaciones del área que una persona puede recorrer en un tiempo determinado según su medio de transporte.
