Documentación Técnica y Marco de Referencia

Red Ciudadana de Seguridad

"Tecnología en tiempo real para la protección y cohesión social"

1. Introducción y Propósito del Proyecto

El presente proyecto aborda la problemática de la inseguridad ciudadana mediante una solución tecnológica multi-plataforma que integra la participación activa del ciudadano con herramientas de monitoreo táctico. La Red Ciudadana de Seguridad no solo actúa como un sistema de alerta, sino como una infraestructura de datos para el análisis preventivo del delito.

2. Marco Teórico: Fundamentos de Arquitectura

2.1 Arquitectura Orientada a Eventos (Event-Driven Architecture)

A diferencia de los sistemas tradicionales basados en peticiones (Request-Response), este proyecto utiliza un modelo basado en eventos. Un evento es cualquier cambio de estado significativo, como la activación de un botón de pánico.

Justificación Académica: El uso de Sockets permite eliminar el "Polling" (consultas frecuentes al servidor), reduciendo el consumo de batería en dispositivos móviles y garantizando que una alerta de emergencia llegue en milisegundos.

2.2 Micro-servicios y Gestión en Monorepo

El código se organiza en un monorepo administrado con un enfoque modular. Esto permite compartir lógica de negocio y definiciones de tipos (TypeScript) entre la API, la aplicación web y la aplicación móvil nativa.

3. Seguridad y Protocolos de Acceso

3.1 Autenticación mediante JSON Web Tokens (RFC 7519)

Se implementa el estándar JWT para la gestión de sesiones. Esto permite una arquitectura "stateless" donde el servidor no necesita almacenar sesiones en memoria, facilitando el escalado horizontal.

3.2 Criptografía y Hashing (Bcrypt)

La seguridad de los datos sensibles se garantiza mediante el algoritmo Bcrypt, que incorpora una función de derivación de claves basada en un cifrado de "Blowfish", incluyendo un "salt" aleatorio para prevenir ataques de tablas arcoíris.

3.3 Seguridad en la Capa Intermedia (Middleware)

Se utilizan herramientas como Helmet para configurar cabeceras HTTP seguras y Rate Limiting para prevenir ataques de denegación de servicio (DoS) y fuerza bruta en los endpoints de inicio de sesión.

4. Sistemas de Información Geográfica (GIS) y Análisis Espacial

4.1 Representación Geoespacial con GeoJSON

Todos los datos de ubicación se almacenan siguiendo el estándar internacional GeoJSON. Esto permite que el sistema sea interoperable con otras herramientas SIG del estado o cuerpos policiales.

4.2 Cálculo de Isócronas y Buffer Geográfico (Turf.js)

Se utiliza la biblioteca Turf.js para realizar análisis espacial en el backend, permitiendo calcular en tiempo real el área probable de desplazamiento de un sospechoso (al alcance de modo de transporte) y rutas de escape seguras para víctimas.

5. Protocolos de Transmisión de Video Digital

5.1 Transmuxing de RTSP a WebRTC

Las cámaras integradas operan bajo el protocolo RTSP (Real Time Streaming Protocol), común en hardware CCTV. El sistema utiliza MediaMTX como media server para transformar estas señales a WebRTC.

Comparativa Técnica: A diferencia de protocolos como HLS que tienen de 5 a 10 segundos de retraso, WebRTC ofrece una latencia sub-segundo, esencial para una respuesta táctica efectiva.

6. Gestión de Estado y UX Reactiva

6.1 Store Centralizado con Zustand

Para la interfaz del Centro de Mando, se utiliza Zustand como gestor de estado. Esto permite una reactividad eficiente donde solo los componentes que reciben una alerta se re-renderizan, optimizando el rendimiento del navegador al manejar cientos de marcadores en el mapa.

7. Infraestructura de Datos y Persistencia

7.1 MongoDB: Base de Datos de Documentos

La elección de una base NoSQL permite una "Agilidad de Datos" superior. El almacenamiento de alertas como documentos JSON facilita la inclusión de metadatos variables (fotos, niveles de audio, logs de dispositivos) sin las limitaciones de una tabla SQL rígida.
